02 · Prefill 启动桥接

先由 Target 为真实 prompt 建立语义，再把 Target auxiliary hidden 投影成 Draft KV

DSparkWorkerV2._forward_prefill() 同时完成三件事：让 Target 正常 prefill 并采出首个 token X；把 prompt 输入行的 FULL auxiliary hidden 注入 Draft KV；把 X@20 封装为下一轮 Draft anchor。X 此刻还没有自己的 hidden/KV。

运行时接收者 scheduler.model_worker : DSparkWorkerV2 → self.target_worker : TpModelWorker固定例子 单请求 · prefix_lens=[0] · extend_lens=[20] · seq_lens=[20]后端假设 CUDA dSpark V2 · PP=1；MLX/NPU/XPU 覆盖路径不由本页推断
输入batch_to_run : ScheduleBatch，forward_mode=EXTEND/MIXED，含 extend_lens/prefix_lens/out_cache_loc
关键捕获capture_hidden_mode=CaptureHiddenMode.FULL，必须得到 Target auxiliary hidden
状态变化Draft KV 写入 prompt/extend 输入行；大 hidden_states 随后清空引用
输出GenerationBatchResult(next_draft_input=DFlashDraftInputV2(bonus_tokens=[X],new_seq_lens=[20]))

主视图 · 启动桥接调用泳道

DSparkWorkerV2 → TpModelWorker → ModelRunner → Target backend → KV injector → Draft KV

每条泳道标明实例与具体类；紫色表示模型/设备执行，蓝色表示 tensor/object 交接。三条站点 route 在 Prefill 阶段共用此流程，差异从后续 decode 才出现。

正常 extend · 非 DP-idle 分支
第 1 步 · 分派 forward_mode.is_extend() || is_extend_in_batch 命中，planner/observer 记录非 decode，然后进入 _forward_prefill()。
第 2 步 · 构造 Target ForwardBatch TpModelWorker 以 CaptureHiddenMode.FULL 调用 ForwardBatch.init_new()。
第 3 步 · runner 分支 ModelRunner._forward_raw() 在 split prefill、prefill CUDA graph、eager extend 中选一条。
第 4 步 · metadata / attention 当前 runner 在需要时初始化 backend metadata，并执行 Target 模型；输出 logits 与 FULL auxiliary hidden。
第 5 步 · 采样 X TpModelWorker 用 Target logits 采样 X 并构造 GenerationBatchResult。
第 6 步 · 发布长度 设置 new_seq_lens=batch.seq_lens=[20]；overlap 在这里提前调用 on_publish()。
第 7 步 · 注入 prompt hidden 校验 hidden/extend/prefix/cache loc，计算 prompt 输入位置，再把 Target auxiliary hidden 投影写入 Draft KV。
第 8 步 · 释放大引用 注入完成后立即 logits_output.hidden_states=None，避免结果对象把整块 tensor 带回 Scheduler。
第 9 步 · 首个滚动锚点 make_next_draft_input() 保存 bonus_tokens=[X] 与 new_seq_lens=[20]，下一轮 Draft 读取。

为什么 / 如果省略 / 功能边界

bootstrap 的正确性条件，比“跑一次 Target”更严格

为什么必须在 Target prefill 之后注入？

只有此时真实 prompt 的 auxiliary hidden、最终位置映射、Target 采样出的首个 token 与 seq_lens 同时可用，Draft 才能从与 Target 对齐的 prefix 状态开始。

没有 FULL hidden

logits_output.hidden_states is None 会立即抛 RuntimeError。若忽略它，Draft 缺少 prompt KV，后续 proposal 的上下文错误；这是正确性失败。

把 X 提前写入 KV

本轮 Target 只计算了 prompt 输入行；X 是这些行预测出来的下一个 token，没有对应的 Target auxiliary hidden。伪造 K/V(X) 会把输出侧 token 与输入侧 hidden 错位。

overlap 提前发布与 hidden 清理

on_publish(new_seq_lens) 在 hidden 校验/注入前触发，让 schedule 准备与后续注入重叠；但 worker 仍会校验并完成注入才返回。注入后把 hidden 设为 None 是显存生命周期优化，不会删除已写 Draft KV。
