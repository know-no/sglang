08 · 折叠快路

folded 不是第四种算法，而是覆盖普通主链的执行位置优化

Draft proposal folded、Target folded accept、optional folded commit 是三层独立能力。前一层成立不推出后一层；任一 guard 失败都必须回到普通实现并汇入同一个可观察结果。

后端边界 当前 DsparkVerifyEpilogue 仅 NVIDIA CUDA共同合同 AcceptOuts → next_draft_input → GenerationBatchResult证据范围 静态源码；未执行 CUDA Graph 回放
输入03 的 proposal.folded、05 的 compact/graph 结果、06/07 的普通尾部合同
本页判断fold_eligible → folded_accept → folded_commit 三层 guard

不负责接受数学见 06/06A；物理 compact rows 见 05；KV/anchor 合同见 07

辅助视图 · 路线与信任边界

“图里执行过”不等于“Worker 会采用”

STATIC · 贪心layout=None，不 compact；proposal 可能折叠，但 Target folded accept 不成立。
COMPACT · 随机采样Target 可以 compact/graph；sampling 令 proposal.folded=false，接受仍在 graph 外按真实 p/q 修正。
FOLDED · 贪心只表示具备命中可能；本轮仍要逐个通过 construction、semantics、compact 与 graph guards。
执行位置Target graph replay 可能已经执行 epilogue 的 scatter/greedy accept；这些 device 操作写入静态 buffer。
采用条件只有 folded_accept=true 才读取这些接受结果。否则应用 grammar/logit 调整后走 06；inject_gate=0 阻止有效融合提交。
08A · warm-up、capture、begin_step 与 replay 到底按什么顺序发生？用 Python/CPU、CUDA stream 与静态 buffer 三条泳道逐轮展开。
为什么 / 如果省略 / 易错边界 / 源码锚点
COMPACT、CUDA Graph、folded 是三个维度

compact 可以 eager；graph 命中也不自动让 accept folded；folded 还要求输出语义不依赖 graph 外调整。

如果省略语义 guard

会采用尚未应用 grammar/penalty/custom processor 的结果，造成错误 token、长度或 KV 提交，而不只是性能变化。
