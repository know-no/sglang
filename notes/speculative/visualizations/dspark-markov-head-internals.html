03A · Markov Head 内部机制

串行的是 logits 修正与采样，不是四次 Transformer forward

四个槽位的 hidden h0…h3 已经一次并行得到。Markov head 只用“上一步真实采样 token”修正当前槽位的基础 logits；它不会把 a/b/c/d 再送回 Transformer，也不会生成这些 token 的新 hidden 或 KV。

共同契约 · markov_head.sample_block(base_logits, first_prev_tokens=X, hidden_states, sampler)动态类 · VanillaMarkov / GatedMarkovHead / RNNHead证据 · sglang.srt.models.dspark 当前源码
输入 · 已完成base_logits[1,4,V]、draft_hidden[1,4,H]、anchor X。
串行状态prev_tokens；RNN 版本还携带小型 state[1,markov_rank]。
输出draft_tokens=[a,b,c,d] 与普通路径的 corrected_logits[1,4,V]。
下一消费者DraftBlockProposer.propose() 封装为 DraftProposal；sampling 的 q 材料交给 06。

主视图 · 并行上半场 + 串行下半场

先同时得到四个 hidden，再按真实 token 依赖逐步采样

每推进一步，只激活一段新的 Markov 依赖；已经完成的 Transformer hidden 不再重算。

真正的依赖：prev_tokens = next_tokens 每步更新；因此后置 token 拥有前置 token 条件。不存在的动作：没有 draft_model_runner.forward(a/b/c)，也没有把 a/b/c/d 写回后置槽位的 Transformer KV。

辅助视图 · 三种具体 head

它们改变“如何算 bias”，不改变“必须按 token 链串行”

动态接收者 · self._proposer.draft_model.markov_head

VanillaMarkov

bias = W2(Embedding(prev_token))

只从上一 token 的低秩 embedding 生成 bias，再加到当前基础 logits。

GatedMarkovHead

gate = σ(Proj([h_k, emb(prev)]))
bias = W2(gate ⊙ emb(prev))

当前槽位 hidden 决定 prev-token bias 的门控强度。

RNNHead

(state_k,bias_k) = rnn_step(state, emb(prev), h_k)

除了上一 token，还跨 step 携带小型 RNN state；仍不调用 Transformer。

会改变 · corrected logits每个 Qk 都加入具体 head 的 bias。
会改变 · sampled tokengreedy 取 argmax；sampling 按 temperature 后分布抽一个。
不会改变 · draft_hiddenh0…h3 已由一次 forward 固定。
不会新增 · Draft KVMarkov 步骤不运行 attention/Transformer，不产生 token 自身的新 KV。
为什么、失败模式与源码锚点
为什么这样拆

昂贵 Transformer 保持一次 block forward；便宜的小头承担 G 步 token 条件，使后置 proposal 能依赖真实前置采样。

误解 · “四步串行等于四次模型”

错。串行 loop 只计算低秩/门控/RNN bias 和 sampler；hidden 与 KV 没有重跑。

sampling 的后继契约

多个 token 的概率都可能非零，但每一步 sampler 只抽取一个 token；完整 Qk 留到拒绝采样修正。

folded 边界

全贪心且 Draft CUDA 图命中时，小头与 sampler 可在图内执行；数学依赖顺序不变。
