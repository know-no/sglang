01A · 专题 · non-overlap / overlap

两种模式都执行隔离事务；差别是跨轮值存在哪里、何时解析，以及异步引用要保活多久

不要把 resolve_forward_inputs() 的“被调用”误读为“一定修改 batch”。non-overlap 的纯 dSpark decode 会穿过这个函数但命中 no-op；overlap 才从 FutureMap 取回上一轮长度、bonus 与附加字段。

共同不变量 都是 restore 后才安装下一轮 DFlashDraftInputV2关键差异 non-overlap 直接提交；overlap 通过 pool-indexed buffer relay证据边界 f01a0c7f97ec · CUDA dSpark V2 · 静态核验
上一轮产物new_seq_lens、bonus 与可选 Draft 附加字段
本页问题这些值何时写、存在哪里、下一轮何时进入 ScheduleBatch
共同结果worker 仍收到正确的 anchor/长度，隔离区外仍恢复 Scheduler 模式
下一消费者DSparkWorkerV2._forward_decode() 或 Prefill bootstrap

主视图 · 两条对齐泳道

沿同一轮时间轴比较，而不是把两个实现拆成互不相干的流程

紫色表示设备 stream/event 或异步生命周期；蓝色表示 buffer/object 数据。三条 STATIC/COMPACT/FOLDED 路线共享这层 Scheduler 机制。

一轮 N 的执行 + 一轮 N+1 的解析
第 1 步 两边进入同一个 Scheduler.run_batch(batch_to_run)，但 overlap 的 batch 携带上一轮 future_indices。
第 2 步 non-overlap resolver 是 guard-only no-op；overlap 先解析长度，再在 forward stream 中解析 bonus/附加字段。
第 3 步 两边都做全字段 snapshot；只有 overlap 把 batch 与 snapshot 压入两槽引用环。
第 4 步 两边都进入同一个 DSparkWorkerV2，只有 overlap 额外传入 on_publish。
第 5 步 overlap 在 worker 中途 publish 新长度并记录 event；non-overlap 只把新长度留在结果对象。
第 6 步 overlap 在 isolation 内把 bonus/附加字段 stash 到 FutureMap，并追加 worker 要求保活的 tensor 引用。
第 7 步 两边都执行 finally restore；临时 Target Verify 视图都不会跨轮。
第 8 步 non-overlap 直接写回 seq/spec；overlap 先持有 next_draft_input，再写 future_indices 把下一轮解析绑定到 FutureMap。
第 9 步 N+1 轮 overlap 通过 event/stream 关系，以 FutureMap 的权威槽位覆盖/物化长度与 bonus，完成闭环。

辅助视图 · FutureMap 与引用保活

省略 record_batch_in_overlap()

异步 forward/copy 仍可能引用 snapshot 中的 GPU tensor，但 Python 引用已离开局部作用域；对象可能被 GC、底层存储可能被 caching allocator 复用，属于生命周期正确性风险。

把 resolver 放回 isolation 内

snapshot 会记录“staging 尚未消费”的旧视图；finally 可能把 prefill_input_ids_cpu/mix_running_indices 恢复回来，造成下一轮重复消费。当前源码特意先 resolve，再 snapshot。
